LED board: GPIO 2, 3, 4, 17, 27, 22, 10, 9 = D0 to D7 = physical 3, 5, 7, 11, 13, 15, 19, 21 (the odd pins down the left column, skipping 9). GND is pin 6. Say it as "2-3-4, 17-27-22, 10-9". Ultrasonic: TRIG 23 (pin 16), ECHO 24 (pin 18), VCC 5V (pin 4), GND (pin 20). TRIG comes before ECHO, 23 before 24.

LCD (4-bit mode): RS=25, EN=24, D4-D7 = 23, 17, 18, 22. RW goes to GND (and pin_rw=None in code). VCC 5V pin 2, GND pin 6.

Touch sensor: OUT=GPIO5 (pin 29), VCC=3.3V (pin 1), GND=pin 9. Buzzer: + to GPIO18 (pin 12), minus to GND (pin 25).

RC522 RFID: it is SPI, so the pins are fixed: SDA 8 (pin 24), SCK 11 (pin 23), MOSI 10 (pin 19), MISO 9 (pin 21), RST 25 (pin 22), 3.3V (pin 1), GND (pin 6). Always 3.3V, never 5V. The LCD and the ultrasonic sensor both use GPIO23/24, but never in the same practical.

2. Fingerprint and camera: how they connect (no GPIO pin hunting)

Fingerprint sensor (R305/R307)

Your PDF's pin table: VCC to 5V , GND to GND, sensor TX (yellow) to Pi RX (GPIO15), sensor RX (white) to Pi TX (GPIO14). TX and RX are always crossed.

Your code opens '/dev/ttyUSB0' , which means the lab sensor is plugged in through a USB-to-TTL adapter. In that case there is nothing to wire on the GPIO header.

Check the port with ls /dev/serial* (your PDF) or ls /dev/ttyUSB* . If the port name differs, change it in the code. This is my note, not in your PDF: with direct GPIO wiring the port is usually /dev/serial0 .

Settings: 57600 baud, address 0xFFFFFFFF , password 0x00000000 .

Templates live in the sensor's own flash memory, each with an ID (position number).

Pi Camera

It plugs into the CSI port (the flat ribbon connector between HDMI and the audio jack). There are no GPIO wires.

Lift the connector latch, insert the ribbon, push the latch down. General rule on a Pi 3B+: the blue tab faces the Ethernet port. Check on your board.

Enable it first: sudo raspi-config then Interface Options then Camera then Enable, then reboot.

Install: sudo apt update , sudo apt install -y python3-picamera2 , sudo apt install -y libcamera-apps .

3. P1: LED blinking patterns

Aim: Interface multiple LEDs with Raspberry Pi GPIO and generate blinking patterns. Wiring: LED board D0 to D7 on GPIO 2, 3, 4, 17, 27, 22, 10, 9 (pins 3, 5, 7, 11, 13, 15, 19, 21). Board GND to pin 6. Library: RPi.GPIO , time . Install: sudo apt install python3- rpi.gpio .

6. P8: Fingerprint sensor (enroll, test, read)

Aim: Interface the R305/R307 fingerprint sensor over UART and perform enrollment and authentication. Library: pyfingerprint (the PDF also lists pip3 install pyserial , which pyfingerprint uses underneath). Connection: see section 2 (USB-TTL on /dev/ttyUSB0 , 57600 baud).

Program 1: test.py (how many templates are stored)

try:

# (port, baud rate, sensor address, sensor password)

correctly

print("Templates stored:", f.getTemplateCount())

else:

print("password verification failed")
except Exception as e:

print("Error:", e)

Program 2: Enroll.py (store a new fingerprint)

from pyfingerprint.pyfingerprint import PyFingerprint

try:

f = PyFingerprint('/dev/ttyUSB0', 57600, 0xFFFFFFFF, 0x00000000) if f.verifyPassword() == False:

raise ValueError('The given fingerprint sensor password is wrong!') except Exception as e:

print('Failed to initialize fingerprint sensor!')
print('Exception message: ' + str(e))

exit(1)

try:

print('Waiting for finger...')

while f.readImage() == False:	# wait until a finger is on the glass

pass

f.convertImage(0x01)	# image -> template in buffer 1

result = f.searchTemplate()	# already enrolled?

positionNumber = result[0]
if positionNumber >= 0:

print('Template already exists at position #' + str(positionNumber)) exit(0)

print('Remove finger...')
while f.readImage() == True:

# wait until finger is lifted

pass

print('Waiting for same finger again...')
while f.readImage() == False:

pass

f.convertImage(0x02)	# second scan -> buffer 2

if f.compareCharacteristics() == 0: # buffer1 vs buffer2, 0 = different fingers

raise Exception('Fingers do not match')

print('Exception message: ' + str(e))
exit(1)

Enroll flow to remember: place finger, readImage , convertImage(0x01) , remove finger, place again, readImage , convertImage(0x02) , compareCharacteristics , storeTemplate . Troubleshooting: wrong baud rate means set 57600. No response means

UART or serial is disabled. No match means enroll again. False rejection means clean the sensor.

Part C: Ultrasonic sensor monitor

import RPi.GPIO as GPIO
import time

GPIO.setmode(GPIO.BCM)

TRIG, ECHO, LED, BUZZER = 23, 24, 2, 18
GPIO.setup(TRIG, GPIO.OUT)
GPIO.setup(ECHO, GPIO.IN)
GPIO.setup(LED, GPIO.OUT)
GPIO.setup(BUZZER, GPIO.OUT)

# Pi sends the trigger pulse # Pi listens for the echo

try:

while True:

GPIO.output(TRIG, 1)	# 10 microsecond HIGH pulse

time.sleep(0.00001)
GPIO.output(TRIG, 0)

while GPIO.input(ECHO) == 0:	# wait for echo to go HIGH

start = time.time()	# note the moment the pulse left

while GPIO.input(ECHO) == 1:	# wait for echo to go LOW

stop = time.time()	# note the moment it came back

d = (stop - start) * 34300 / 2 # speed of sound 34300 cm/s, halve it for one-way

print("Distance:", round(d, 2), "cm")

if d < 20:

print("Object Detected")
GPIO.output(LED, 1)
GPIO.output(BUZZER, 1)

else:

print("No Object Detected")

GPIO.output(LED, 0)
GPIO.output(BUZZER, 0)
time.sleep(1)

except KeyboardInterrupt:

GPIO.cleanup()

Ultrasonic logic to remember: TRIG HIGH for 10 microseconds sends an 8-pulse burst. ECHO stays HIGH for as long as the sound takes to go out and come back. Distance = time x 34300 / 2. The threshold in the lab program is 20 cm. HC-SR04 ECHO outputs 5V , and a Pi GPIO is only 3.3V tolerant, so a voltage divider on ECHO is the proper practice. The PDF does not mention one, so ask your lab what they use.

def get_distance():

GPIO.output(TRIG, False)

time.sleep(0.05)	# let the sensor settle

GPIO.output(TRIG, True)

time.sleep(0.00001)	# 10 microsecond pulse

GPIO.output(TRIG, False)

start = time.time()
stop = time.time()
timeout = time.time()

while GPIO.input(ECHO) == 0:

start = time.time()

if time.time() - timeout > 0.05: # safety timeout, avoids hanging

return 0
timeout = time.time()

while GPIO.input(ECHO) == 1:

stop = time.time()

if time.time() - timeout > 0.05:

return 0

elapsed = stop - start

distance = (elapsed * 34300) / 2
return round(distance, 2)

13. Pattern cheat: how the programs are built

1. Output device (LED, buzzer): setup(pin, OUT) , then output(pin, 1 or 0) .

2. Digital input sensor (touch, gas, rain): setup(pin, IN) , then if GPIO.input(pin): ... . Touch is HIGH when touched. Gas and rain in your PDF are LOW when detected.

3. Ultrasonic: TRIG pulse, time the ECHO, distance = time x 34300 / 2.

4. Fingerprint: readImage , convertImage(0x01) , searchTemplate , then check position >= 0 (P11, P12) or == -1 (P8 Read.py).

5. Always finish with try / except KeyboardInterrupt / GPIO.cleanup() .

14. Quick viva answers

GPIO: General Purpose Input Output, programmable pins on the Pi.

BCM vs BOARD: BCM uses the chip's GPIO numbers, BOARD uses the physical pin positions.

Why GPIO.cleanup() : releases pins and resets them so nothing stays driven. UART: Universal Asynchronous Receiver Transmitter, two wires (TX, RX), crossed between devices. The fingerprint sensor uses 57600 baud.

Fingerprint template: minutiae data (ridge endings, bifurcations), not a photo of the finger.

Enrollment vs authentication: enrollment stores a template, authentication searches for a match.

SPI: serial protocol with MOSI, MISO, SCK and a chip-select (CE0). The RC522 uses it at 13.56 MHz.

CSI: Camera Serial Interface, the ribbon port for the Pi Camera.

I2C: two wires, SDA and SCL. An I2C backpack saves LCD pins.

Flask: lightweight Python web framework. A route maps a URL to a Python function. HTTP request-response: the browser sends a request, Flask runs the function, GPIO is updated, and HTML is sent back.

Ultrasonic principle: sound pulse out, echo back, distance = (time x speed of sound) /

2.

Sensor vs actuator: a sensor reads the world (touch, ultrasonic), an actuator acts on it (LED, buzzer).

15. Last-minute checks before you run anything

Pins are in BCM numbers in the code, but the board and module labels refer to physical pins. Use the master pin table in section 1.

Fingerprint code fails if the port is wrong. Check ls /dev/ttyUSB* first.

RC522 needs SPI enabled, and the camera needs enabling in raspi-config, followed by a reboot.

Flask serves templates from a folder named exactly templates .
If you get a GPIO permission error, run with sudo .

If a program hangs, press Ctrl+C. Every program here catches it and cleans up.

16. BOARD mode version (physical pin numbers only)

Your teacher allowed GPIO.BOARD . Two things change in every program: the setmode line, and every pin number becomes the physical pin from the wiring tables. Everything else stays the same.

GPIO.setmode(GPIO.BOARD)

# instead of GPIO.BCM

Never mix modes in one program. If you use BOARD, every pin in that program must be a physical pin number.

BOARD-mode summary to memorise

LED board: 3, 5, 7, 11, 13, 15, 19, 21 (odd numbers going down, skip 9). GND 6. Ultrasonic: TRIG 16, ECHO 18, VCC pin 4, GND pin 20.

Touch: OUT 29, VCC pin 1, GND pin 9.
Buzzer: + 12, minus pin 25.

LCD: RS 22, EN 18, D4 to D7 = 16, 11, 12, 15.

Viva line: BOARD mode refers to the physical pin number on the 40-pin header, BCM refers to the Broadcom chip's GPIO number.
